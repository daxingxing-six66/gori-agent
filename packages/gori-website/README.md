# Gori 交互式宣传站

独立 npm workspace：`@gori/website`。面向个人开发者，以“用自然语言管理服务器”为主线。与 `ssh-agent-web` 产品 UI 分开，不改变产品首页或核心构建、启动流程。

## 本地开发

在仓库根目录完成 `npm ci --ignore-scripts` 后：

```sh
npm run dev:website
```

打开 http://127.0.0.1:4188 。端口被占用会明确失败，不结束已有进程。可用 `npm run dev --workspace=@gori/website -- --port 4190` 指定其他端口。

```sh
npm run check --workspace=@gori/website
npm run build:website
npm run preview:website
```

构建产物为本 package 内的 `dist/`，支持普通静态托管。相对资源路径支持部署到子目录。当前按仓库内 package 交付，尚未注册或部署线上 Sites。

## 三个设计方案

三版共用功能数据与工作台演示，页面结构和浏览方式分别设计。Tabby / Mono 的方案比较器在页面底部；Studio 的比较器收进全屏“探索”菜单：

- `/?design=tabby`（默认）：暖白/炭黑/琥珀色、左对齐大标题、原创 ASCII 波形纹理、交替的功能与界面示例。
- `/?design=studio`：终端数据流驱动的完整页面。全屏四幕依次呈现“意图 → 命令 → SSH → 观测”，同一 Canvas 字符场随原生滚动连续变形；随后进入横向能力展廊、授权决定与开始使用。工作台通过全屏 dialog 打开，不再把常规功能网格接在一个装饰模型后面。
- `/?design=mono`：黑白编辑风格；超大描边英文标题、非对称中英文信息、线框、方形控件、紧凑的双列能力网格。

URL 参数仅允许这三种值，其他值回到默认方案。最终选定方案后可以单独保留，比较入口不属于必须保留的产品功能。

Studio 的字符流是为 Gori 重新设计的视觉叙事：用固定的命令、日志、数据包和透视轨道说明从自然语言到操作结果的过程。它不是服务器监控，也不是实际 SSH 执行结果。

## 文件职责

- `index.html`：公共静态页面、方案入口及可复用的工作台、审批、安装和 FAQ 节点。
- `src/main.js`：仓库链接、移动导航、审批交互、安装命令复制及失败降级。
- `src/demo.js`：场景/步骤切换、键盘操作、主题、文件示例导航。
- `src/scenarios.js`：预设场景数据与结果片段；从真实功能契约提炼，均非真实执行记录。
- `src/dom.js`：检查 DOM 边界。
- `src/designs.js`、`src/designs.css`：三版入口、ASCII 纹理和各方案样式装配。
- `src/tabby.css`、`src/mono.css`：暖色终端与黑白编辑方案的独立样式。
- `src/studio.html`：Studio 专用四幕叙事、能力展廊、授权与开始使用、工作台和探索 dialog。
- `src/studio-page.js`：挂载专用布局，把公共工作台/审批/安装/FAQ 节点移动到相应位置，管理 dialog、关闭后的焦点恢复与按钮指针反馈。
- `src/studio-scene.js`：统一滚动进度、章节/HUD、意图与数据包交互、展廊位移，以及暂停、减少动态效果、可见性和资源释放的控制器。
- `src/studio-dataflow.js`：原创 Canvas2D 透视字符场、轨道与数据包绘制；接收控制器传入的时间、滚动进度、指针与脉冲，不持有独立 RAF 或输入监听。
- `src/studio-experience.css`：Studio 全屏场景、章节转场、横向展廊、菜单/dialog，以及窄屏与减少动态效果下的布局。
- `src/styles.css`：页面视觉与响应式布局。
- `src/workspace.css`：演示工作台及明暗主题。
- `vite.config.js`：Vite 静态构建、相对资源地址、开发和预览端口。

只使用 Vite 与 TypeScript 开发依赖，版本与仓库已有依赖一致。数据流使用浏览器原生 Canvas2D 做透视投影，不引入三维运行时依赖。页面不引入第三方字体、分析脚本或外部图片；不调用 Gori API、模型、SSH 或生产数据。

## 交互与边界

- 公共工作台默认展示读取内存后的示例，可重新开始、逐步推进、点选步骤或切换场景。Studio 从首屏或能力展廊入口打开全屏工作台 dialog，继续复用四场景的原数据与行为。
- 部署依次展示计划审阅、构建、上传、重启、健康验证和明确结束；重启步骤标注示例已审批。计划确认不代表 Full Access 授权。
- 排障从方向、日志、端口核对到结论；示例中的配置差异不是实际服务器诊断结果。
- 文件场景可打开 logs、预览 application.log、查看 config 示例和返回上级；不是浏览器直接访问远端文件。
- 独立权限示例支持批准、拒绝与复位，不执行命令。
- 工作台明暗主题只影响演示，不改系统或产品设置。
- Studio 使用原生页面滚动与 sticky 场景，不监听 wheel 来接管或阻止滚动。四幕共享一个画布，滚动同时改变章节文字、示例 HUD 与数据流的聚合/通道/结果形态；章节按钮也可直接跳转。
- 意图按钮选择要跟随的预设任务；发送意图和点击数据包只触发视觉响应。最终结果入口可以打开对应的工作台演示，不执行命令。
- 桌面能力展廊将原生纵向滚动映射为横向位移；窄屏与减少动态效果偏好下改为纵向布局。每项功能仍有可操作的示例入口。
- 动态视觉可暂停，控制器处理减少动态效果、页面/场景可见性与资源释放。Canvas2D 不可用时保留静态字符背景与 DOM 内容；视觉停止或降级不应阻断章节内容和工作台入口。
- 工作台和探索菜单使用原生 dialog。关闭或 Escape 后恢复触发按钮焦点，章节链接关闭 dialog 并聚焦目的章节；探索菜单中保留方案比较入口。
- 场景 Tab 支持左右方向键、Home/End；原生按钮/链接支持键盘；FAQ 使用原生 details。减少动态效果偏好会关闭平滑滚动与过渡。
- 禁用脚本时保留产品介绍、工作方式、安装命令、FAQ 和导航；交互按钮隐藏。

本地运行不表示模型上下文不离开电脑；页面明确说明模型请求发往所选供应商。Session 命令沙箱不等同于完整主机隔离，也不覆盖 SFTP。平台和发行状态链接到根验收文档，未宣传全平台实测或独立安装包。

## 本轮验收（2026-10-23）

- Studio 在 1440、390、320px 宽度检查页面宽度，没有横向溢出；手机展廊为纵向布局。Tabby / Mono 桌面入口和 Mono 320px 回归正常。
- 浏览器实际操作：原生 PageDown 推进四幕、章节按钮跳转、意图/HUD 同步、部署结果进入对应工作台、数据包反馈、暂停状态、横向能力切换、全屏菜单章节跳转与焦点恢复。
- 全屏工作台实际操作：部署计划到健康验证、诊断到保存结论、文件 logs/config/返回、明暗主题、关闭和 Escape 后恢复触发焦点、工作台内部链接返回能力展廊。
- 批准/拒绝/复位、展开安装、复制成功提示、FAQ 展开通过；浏览器未出现新增 error/warn。
- 宣传站类型检查、静态构建和根 `npm run check` 通过。提交前另对仅含宣传站变更的暂存快照运行路由与源码摘要校验，通过；其他会话修改未混入提交。减少动态效果、无 Canvas2D、后台可见性和 bfcache 生命周期做了源码核对，未模拟系统设置或浏览器故障。未执行真实模型、SSH 或服务器操作。
