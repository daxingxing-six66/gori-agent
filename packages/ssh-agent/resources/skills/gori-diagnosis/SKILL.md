# Gori 诊断记录规范（v2）

这份指引规定诊断任务的**节点输出契约**。目标是留下"可追溯、可复核、粒度一致"的记录，而不是事后补写报告。

## 一、总原则

1. **证据驱动**：节点由"关键证据"触发，不由"检查步骤"或"时间"触发。
2. **一证一节点**：一个节点只承载一条关键证据及其判断。
3. **节点只写证据，不写报告**：结论性长文只出现在 `diagnose_finish` 的 Markdown。
4. **正负成对**：每条禁止项都必须配一个可执行的正向动作。

## 二、流程契约（必须按序执行）

| 阶段 | 动作 | 要求 |
|---|---|---|
| 开场 | `diagnose_update` → append | **必须**。`direction`=要回答的问题（一句话）；`status`=diagnosing；`explanation` ≤150 字（已知线索/范围/约束）|
| 取证 | 每获得一条关键证据 → append | **必须**。一证一节点，模板见第三节。不得积压到最后一次性补写 |
| 进展 | 同一证据出现新进展 → update_current | 不新增节点 |
| 收口 | `diagnose_finish` | 完整结论 Markdown；节点不承担结论 |

> 开场节点不是"计划节点"：它只写"要回答什么、已知什么、边界在哪"，不写步骤清单。

## 三、节点模板（三个字段，缺一不可）

- **`direction`**：一句话，≤40 字。写"该证据支持的判断"或"正在核对什么"。
- **`status`**：`diagnosing`（正在验证）/ `confirmed`（该判断有支撑，≠整个问题解决）/ `unconfirmed`（无法判断，须说明限制或停止理由）。
- **`explanation`**：固定三段、各一行，**总计 ≤300 字**：
  - `证据：` 原文片段 / 文件:行号 / 统计值 / 时间点（可复核）
  - `范围：` 查询窗口、样本量、是否选择性观察
  - `边界：` 未知项、可能反例、结论不适用之处

**禁止**在 `explanation` 中出现：计划、命令清单、多级小标题、报告式结论、第二条独立证据。

## 四、什么算"关键证据"（必须落节点）

- 日志命中行（含时间、线程、关键字段）
- 代码抛出点 / 分支条件（文件:行号）
- 数据统计（计数、分布、时间线拐点）
- 配置或部署事实（版本、启动时间、开关值）
- 反证（排除某个解释的证据）

**不落节点**（留在分析过程中）：命令本身、计划、重复观察、无信息量输出、同一事实的再次确认。

## 五、好 / 坏对照

**坏（一个节点塞满全部内容）**
`direction`=定位某报错原因；`explanation` 写"来源 + 最近一次 + 分布 + 结论 + 边界"五段式长文。

**好（按证据拆分）**
1. `direction`=该文案来自活动报名服务
   `证据：WangxinbanRegistrationService.java:37 BLOCKED_MESSAGE`；`范围：全仓 grep`；`边界：未核对线上部署版本一致`
2. `direction`=最近一次触发是 IP 限额
   `证据：2026-10-20 14:33:55.657 WARN reason=IP_LIMIT, ip=49.74.216.58, count=3`；`范围：当日 live info`；`边界：未回溯更早归档`
3. `direction`=当日拒绝以 IP 限额为主
   `证据：IP_LIMIT 479 / PREFIX 49 / IDENTITY 40，涉及 59 用户`；`范围：当日全量命中`；`边界：其他原因与统一文案无法一一对应`

## 六、结论规则（`diagnose_finish`）

- 节点不写结论长文；结论在 Markdown 中组织。
- 结论按 **已证实 / 高概率 / 无法证实** 分级，保留观察窗口与适用范围。
- 信息不足可提交 inconclusive 结论，说明已知事实、未知项与限制。
- 报告可引用节点序号，但**不复述节点全文**。

## 七、提交前自检（每条节点）

1. 是否只含**一条**关键证据？
2. `explanation` 是否恰好三段、总计 ≤300 字？
3. `direction` 是否一句话、≤40 字？
4. 是否混入了结论、报告或计划？
5. 该节点能否**独立读懂**（不依赖前后文）？

任一项为"否"，先修正再提交。

## 八、常见反模式 → 正确动作

| 反模式 | 正确动作 |
|---|---|
| 全程不记录，最后直接给结论 | 开场即建方向节点；每条关键证据立即落节点 |
| 一个节点写完整推理链 | 拆成多个节点，一证一节点 |
| 把"下一步计划"写成首节点 | 首节点只写问题、已知、边界 |
| 节点里贴大段日志/命令输出 | 只摘可复核的关键片段（含定位） |
| 用模糊表述（"看起来""可能"）代替事实 | 写清证据原文与来源；不确定就标 `unconfirmed` 并说明理由 |
| 结论写进节点 | 结论进 `diagnose_finish` 的 Markdown |
