# 任务容器与 Terminal 重构约束

确认日期：2026-10-13（Asia/Shanghai）。状态：约束已确认；2026-10-13 用户授权规划与实现 Terminal 容器第一阶段。当前实现和验证边界见 [任务容器功能文档](../ai-repo/task-container.md)。

2026-10-14 补充：用户授权容器放大及收起展示，最终范围是右侧任务 Tab 容器向左覆盖 Agent 对话区，左侧服务器导航继续可见、可操作。该补充只改变容器展示，不扩大任务业务范围。

本文保存本轮讨论的最终决定，供上下文压缩、多轮开发或换会话后继续使用。涉及任务容器、Terminal Tab，以及后续 Deploy/Monitor 接入时，先阅读本文，再核对 [AI 代码路由](../ai-repo/index.md) 指向的真实源码。

本文描述目标和约束，不代表功能已经实现。当前行为以源码及功能文档为准；实施后同步更新功能文档与源码映射。用户后续明确修订约束时，应更新本文，避免只把新决定留在聊天中。

## 1. 目标与本次范围

右侧 Terminal 区域升级为可承载不同任务页面的 Tab 容器。Terminal 是第一阶段唯一接入的任务页面。

- 第一阶段：拆分容器和 Terminal，接入标签栏，调整打开、定位与关闭交互，保留 Terminal 的现有运行能力。
- 后续方向：接入 Deploy、Monitor 等任务，并逐步抽象轻量工作流。工作流的任务身份、状态、执行与恢复需要前后端共同设计，不能仅用前端 Tab 包装代替。
- 本阶段不实现 Deploy/Monitor Tab、多个 Terminal 实例、任务并行调度或通用工作流引擎，不迁移现有部署 UI。
- 2026-10-13 用户已授权按本文约束自行规划与实现第一阶段。继续开发时先恢复这些约束，维持本阶段范围；后续 Deploy/Monitor 和工作流设计仍按各自任务推进。

## 2. 第一优先级：可读性与解耦

代码可读性和容器与业务模块的解耦是本次重构的第一优先级。抽象应帮助定位职责和理解调用关系，保持小而直接。

### 职责分层

| 层 | 职责 | 边界 |
|---|---|---|
| Tab 容器 | 展示标签栏和当前页面，处理选中/切换，发出关闭请求，根据标签数量展开或收起区域 | 不导入 Terminal/Deploy/Monitor 业务实现，不调用业务 API，不通过任务类型分支编排业务 |
| 功能模块 | 各自维护页面内容、展示状态、运行生命周期，以及是否允许关闭和如何关闭 | Terminal 的连接、状态查询、输出订阅、重试与关闭继续由 Terminal 模块负责；未来其他模块各自定义关闭语义 |
| 会话装配层 | 将功能模块接入容器，衔接 Composer 入口，决定打开/选中哪个 Tab，并在业务关闭完成后移除 Tab | 装配层可以认识具体功能，但只表达接入关系，不堆积业务执行逻辑 |

### 共用契约

- 容器接收通用的标签身份、标题、页面内容、必要的展示状态和关闭请求能力。字段和类型名称在实现时确定，不预先固定复杂 Schema。
- 关闭能力应表达是否允许关闭、关闭中的状态，以及必要的禁用原因；容器不能根据 Terminal 状态名自行推导这些业务规则。
- 容器发出关闭请求后，由功能模块的控制逻辑完成业务关闭，装配层据实际结果决定何时移除 Tab。请求失败不能被当作关闭成功。
- Terminal 的完整业务状态保留在 Terminal 模块，后端继续提供生命周期事实。容器不维护另一套会与后端冲突的运行状态。
- 将来添加功能模块时，应主要修改新模块和接入关系，通常不需要修改容器实现。
- 容器布局和标签交互集中在容器模块，Terminal 运行逻辑集中在 Terminal 模块。保持清晰的依赖方向，不引入循环依赖或让业务模块反向操纵容器内部状态。

## 3. 已确认的交互

**最终决定：`/` 菜单中的 Terminal 是“打开或定位”入口。已经打开时再次选择，定位到当前 Terminal Tab，不关闭 Terminal。关闭通过标签页的 `×` 完成。**

这条决定覆盖讨论中曾短暂选择的“保留开关行为”。现有实现仍是开关时，不应把旧行为误当作本次目标。

| 场景 | 目标行为 |
|---|---|
| Terminal 未打开，从 `/` 菜单选择 | 展开容器，创建并选中 Terminal Tab，调用现有打开接口，在该页内显示连接过程 |
| Terminal 已打开，再次选择 | 定位到已有 Tab，保留终端内容和滚动位置，不重复调用打开接口、不重建终端 |
| Terminal 正在连接，再次选择 | 定位到同一个 Tab，不重复创建页面或发起打开请求 |
| 点击已连接 Terminal 的 `×` | 调用现有关闭接口，进入关闭过程；关闭完成后移除 Tab；最后一个 Tab 移除后收起容器，聊天区恢复宽度 |
| 打开失败 | 保留 Terminal Tab，在该页内展示错误和现有重试能力；点击 `×` 收起失败页。若已无运行终端，收起错误页不等于再次关闭进程 |
| 关闭请求失败 | 保留 Tab，刷新后端状态并显示错误，不先移除页面或假定终端已经结束 |
| 刷新页面或重新进入会话 | 查询现有状态；仍在运行则恢复容器与 Tab，附着到原终端，不额外创建 Terminal 实例；正在过渡则按后端状态恢复对应过程 |

补充规则：

- 第一阶段同一业务 Session 最多一个 Terminal Tab，沿用后端一个 live TerminalSession 的约束。容器的扩展能力不代表本阶段支持多个 Terminal 或并行任务。
- 定位已有 Tab 是展示操作，Agent 运行时也可进行。新开和关闭 Terminal 继续遵守现有运行限制；Agent 正在执行时关闭入口禁用并说明原因，不隐含停止 Agent。
- 连接、关闭及状态读取期间避免重复生命周期请求。定位已有页面与发起业务请求需要分别判断，不直接复用旧模式开关的整项禁用逻辑。
- 打开/定位继续使用即时 UI Action，不额外发送用户 Chat 消息或创建 Agent Tool Call；后端原有的模式 system 记录继续保留。
- 关闭流程沿用现有清理和连接过渡机制，复用现有接口；关闭 Tab 代表关闭 Terminal，而非仅隐藏一个仍运行的终端。

## 4. 页面身份与运行生命周期

- Tab 的选中状态与功能的运行状态分别管理。切换页面不能因为暂时不可见而关闭连接、停止任务、清空内容或丢失状态。
- Terminal Tab 表示当前 Session 的 Terminal 功能，不直接等同于某一次底层 TerminalSession 实例。
- 修改沙盒配置导致旧终端关闭并自动重开时，保留同一个 Tab，在页内反映重开状态；实际连接身份按后端新实例更新。
- 页面刷新、离开会话时的浏览器 attachment 清理，与用户点击 `×` 请求关闭 Terminal 是不同操作，不能混用。
- 后端状态与现有重连/终态策略仍是事实来源。恢复页面不代表恢复已丢失的 Shell；后端重启后不得伪造旧终端仍存活或自动重放输入。
- 保留 xterm、snapshot/SSE 恢复、Observation Lens、主题更新和后端权威 geometry/resize ownership。容器负责布局，不自行修改 PTY 网格或接管运行协议。

## 5. UI 约束

- UI 质量是重要验收项，沿用已重构的主题配色和颜色层次，避免加入冗余信息。
- 标签栏承接现有 Terminal 顶栏的位置，下方直接放终端内容；Terminal 名称和连接状态避免在容器标题、标签和内部标题中重复出现。
- 容器表面与终端视口继续分层，不把 Terminal 的深色外观强加给未来所有页面。通过既有主题系统表达颜色。
- 当前只接入 Terminal，保持界面克制，不增加任务列表、宣传空态或与本阶段无关的工作流入口。
- 先确认交互逻辑，再推进视觉和实现。此前聊天中的两份 UI 草图未获用户认可，不作为已确认的设计或实现依据。
- 具体标签样式、间距和响应式视觉需要后续结合成品核对，本文不固定未经确认的视觉稿。

## 7. 实施时的验收重点

1. 容器无需了解 Terminal 业务即可展示页面并发出关闭请求；具体业务由功能模块和装配层承接。
2. `/` 首次打开；重复选择只定位，内容与滚动位置保留，页面和打开请求均不重复。
3. `×` 确实执行现有关闭流程，正确处理禁用、过渡、成功和失败；最后一个 Tab 关闭后容器收起。
4. Agent 运行时可以定位已有 Tab，新开和关闭继续受原运行限制约束。
5. 打开失败可在原 Tab 重试或收起；刷新恢复运行中的终端不额外创建实例。
6. 沙盒自动重开保持同一个 Tab，连接身份更新；既有输出、Observation、主题和 resize 行为不被布局拆分破坏。
7. 视觉沿用现有主题，信息不重复，不借本次重构扩展未纳入范围的功能。
8. 代码改动后完整核对受影响源码与功能文档，再按 [agent.md](../../../agent.md) 执行文档防腐及代码检查；没有修改实现前，不把这些目标写成已经完成的功能。

## 8. 容器展示模式与尺寸同步

- 停靠、放大、收起由通用容器展示层及会话装配层管理，不归 Terminal 或未来 Deploy 的业务生命周期。
- “全屏”指右侧任务容器连同标签栏向左放大，覆盖会话主体中的页首、Agent 对话与输入区；不覆盖左侧服务器导航，不进入浏览器原生全屏。退出后恢复原停靠布局，支持 Escape；左侧导航在放大期间仍可操作。
- 收起只隐藏任务内容；桌面保留右侧窄恢复栏，窄屏保留恢复行。恢复或 Composer 定位已有任务时展开原页面，不重复 open、attach 或发送 Chat 消息。实际关闭仍由标签页 `×` 请求业务关闭。
- 展示切换保留同一任务页、输出订阅、内容和草稿；切换 Session 或最后一个任务移除后复位为默认停靠模式。放大时仅让被覆盖的对话控件退出键盘和无障碍导航，不禁用服务器导航。
- Terminal 用实际可见视口测量 resize，收起和隐藏页面不提交零尺寸或最小尺寸替代值。隐藏时释放 resize ownership；恢复时重新申请并测量，普通展示切换不重建连接。
- resize 请求防抖并串行发送，过渡中只取最新测量；服务端 `terminal.resized` 确认后再更新浏览器 xterm。失去 ownership 的旧响应、卸载后的回调不得覆盖当前状态；后端继续校验 ownership epoch 和 geometry 边界。

## 9. 2026-10-22 人机协作实验补充

用户确认扩展原只读边界：Agent 空闲时用户点击终端可完整交互，发送聊天即交回，Agent 运行及等待审批期间不可接管。人工沿用原 PTY 沙盒、免逐键审批，可见记录与当前画面在首次模型请求前同步，隐藏输入不持久化。前台进程保持，Agent 写入前先观察；输入状态行和协调逻辑归 Terminal，容器职责、布局和 resize 协议保持。实现与验证边界见 [人机协作](../ai-repo/features/terminal-human-interaction.md)。
